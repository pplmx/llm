### Changed

- **Test architecture — runtime + GPU-less strategy**:
  - `just test-fast` / `just test-parallel` are now the **CPU-clean daily gate**
    (exclude `heavy`, `e2e`, and *all* GPU markers); new `test-gpu`,
    `test-heavy`, and `test-cov-fast` (core + coverage) recipes.
  - `tests/conftest.py::pytest_collection_modifyitems` now auto-skips **all**
    GPU-requiring markers (`gpu` <1, `multi_gpu` <2, `need_gpu(n)` <n,
    `full_cluster` <8) via usable-GPU count, so a GPU-less host *skips* GPU-only
    / too-slow-on-CPU tests instead of failing or hanging.
  - An autouse `_force_wide_terminal` fixture sets `COLUMNS=120`/`LINES=40`, so
    rich/typer `--help` is not truncated by ambient terminal width — fixing 5
    CLI-help tests that dropped option names (`--model`/`--host`) on narrow-width
    CI runners.
  - Fixed a CUDA-invalid SDPA test reference (`attn_mask`+`is_causal=True`) in
    `test_sdpa.py` and gated the GPU-dependent `gpus_per_node` test with
    `need_gpu(2)`.
  - **CI**: per-push `build-and-test` runs `just test-cov-fast` (fast core +
    coverage, previously the 6 h full suite); added a scheduled `test-full` job
    running `just test-cov` (full suite + coverage) on the weekly schedule.
  - New design doc [`docs/development/test-architecture.md`](docs/development/test-architecture.md).
- **Unified `llm` CLI (breaking)**: the six flat `llm-train` / `llm-serve` /
  `llm-quantize` / `llm-prune` / `llm-decompose` / `llm-migrate-ckpt` console
  scripts are replaced by a single `llm` command whose subcommands carry each
  tool's options: `llm train`, `llm serve`, `llm quantize [gptq|fp8]`, `llm
  prune`, `llm decompose`, `llm migrate-ckpt`. New `llm.cli.main` root app
  composes them (leaf commands use a group callback + `invoke_without_command`,
  `quantize` stays a real subcommand group); `python -m llm` also works. All
  docs / README / user-facing advice strings updated to the new names.

### Added

- **Astral pre-commit hooks + separate tool configs** (dev tooling):
  `.pre-commit-config.yaml` now adds the maintained
  [`astral-sh/uv-pre-commit`](https://github.com/astral-sh/uv-pre-commit)
  `uv-lock --check` hook (fails a commit when `uv.lock` is stale with
  `pyproject.toml`, preventing silent dep drift such as torch on the next
  `uv run`) and [`astral-sh/ty-pre-commit`](https://github.com/astral-sh/ty-pre-commit)
  `ty` hook (replacing the hand-rolled local hook). The command runner moved
  from `Makefile` to a `Justfile` (`just` http://just.systems; CI installs it
  via `taiki-e/install-action@just`). All `just test*` targets (and the
  pre-commit doctests hook) run `uv run --frozen`, so running the suite never
  silently rewrites `uv.lock` (e.g. a stray re-lock bumping torch mid-run);
  `just sync`/`just dev` remain non-frozen for intentional re-locks. To avoid
  bloating
  `pyproject.toml`, pytest config moved from `[tool.pytest]` to a standalone
  `pytest.toml` (`[pytest]` table, pytest 9 native TOML), and a new `ty.toml`
  scopes the type-check to `src/llm/` (matching the CI `ty check src/llm/` gate;
  non-src dirs are intentionally not type-clean).

- **Flash Attention & Paged Attention full-path integration confirmed**
  (previously listed under "Planned", now shipped): the `llm.core.attn.flash_attn`
  backend (``attn_impl="flash_attn"``) and the paged-attention full model forward
  path (``llm.core.paged_attention`` ``PagedKVCache`` + ``paged_attention_forward``,
  ADR-004) are wired through the decoder forward, serving continuous batching /
  prefix cache, and training; both carry dedicated test suites

- **SimPO alignment** (ROADMAP 11.4):
  `llm/training/tasks/simpo_task.py` -- reference-free, length-normalized
  preference optimization (`--task simpo`, Meng et al. 2024). Implicit reward
  = `beta * mean log p(y)`; loss = `-log sigma(beta*(mean_logp_w - mean_logp_l) - gamma)`
  plus a chosen-response SFT regularizer (`lambda`). No frozen reference model
  (avoids DPO's divergence / checkpoint-restore complexity); reuses
  `DPODataModule` and the standard loop. Config knobs `simpo_beta` /
  `simpo_gamma` / `simpo_lambda`. Verified reference-free, finite+backprop,
  directional (chosen preferred on a fixed batch) and an engine e2e.

- **GGUF Q3_K write path**:
  `llm/export/gguf/quant.py::quantize_q3_k` packs the 256-wide `block_q3_K`
  (hmask32+qs64+scales12+d2, 16 groups of 16, value = dl*q with q = ql-(qh<<2),
  signed 6-bit scales) matching the gguf-py-verified `dequantize_q3_k` exactly,
  wired into the exporter (`quantize="q3_k"`, file type 11). This completes the
  K-quant family — **all five** reader-supported K-quants (Q2_K..Q6_K) are now
  exportable.

- **GGUF Q2_K write path**:
  `llm/export/gguf/quant.py::quantize_q2_k` packs the 256-wide `block_q2_K`
  (scales16+qs64+d2+dmin2, 16 groups of 16, value = dl*q - ml) matching the
  gguf-py-verified `dequantize_q2_k` exactly, wired into the exporter
  (`quantize="q2_k"`, file type 10). This completes every common llama.cpp
  K-quant export path.

- **Asymmetric simple-PTQ**:
  `llm/quantization/ptq.py::QuantizedLinear.from_linear` now supports
  `QuantConfig(symmetric=False)` — 8-bit scale + zero-point weight
  quantization, per-tensor and per-channel. The unsigned grid is stored as
  `q - 128` in the int8 buffer with the offset folded into `weight_zero_point`
  (dequant stays `(q - zp)*scale`). Accurately represents skewed weight
  distributions (asymmetric strictly beats symmetric on all-positive /
  all-negative rows).

- **GGUF memory-mapped reading**: `GGUFReader` now maps
  the file read-only with `mmap` instead of copying the whole payload into RAM,
  so large exported models load with lazy, page-cached weights (ideal for
  serving). Parsing/metadata/`read_tensor`/`read_tensor_raw` are unchanged;
  added `close()` (idempotent) for explicit resource release.

- **Native ZeRO Stage-1** (ROADMAP 15.5):
  - `llm/training/distributed/zero.py`: `ZeroOptimizer` partitions
    optimiser-state across data-parallel ranks (~1/`world_size` per rank,
    round-robin by flat index), all-gathers the full updated weights each step,
    and exposes `state_dict()`/`load_state_dict()` as a per-rank shard
    (FSDP-sharded style) for checkpoint/resume. It is a `torch.optim.Optimizer`
    subclass, so it works with schedulers / the (disabled) GradScaler path.
  - `TrainingTask.build_optimizer_for(params)` builds an optimizer over an
    arbitrary parameter subset through each task's own `build_optimizer`.
  - New `parallel_strategy="zero"` (engine standard loop): the engine averages
    the world-group gradients at step boundaries (classic ZeRO-1 reduction, no
    DDP wrapper — identical CPU/gloo and CUDA semantics), builds a per-rank
    `ZeroOptimizer`, and uses the sharded state for checkpointing. v1 refuses
    custom-loop tasks and fp16 AMP (bf16/fp32 OK). Verified with a 2-rank
    CPU/gloo engine e2e (finite loss, disjoint shards, bit-exact lockstep).
    Docs: [distributed guide](docs/guides/distributed.md).

- **Rejection Sampling** (ROADMAP 阶段十一):

- **GRPO (Group Relative Policy Optimization)** (ROADMAP 阶段十一):

    `grpo_clip_eps` / `grpo_kl_beta`. Initial-policy log-probs are snapshotted as

    hit-rate 0 -> ~1). Docs: [GRPO guide](docs/guides/grpo.md) + CLI reference row.

- **SmoothQuant integration** (阶段十三 §13.3, P1 量化深化): INT8 weight+activation quantization (Xiao et al., ICML 2023) — the second deferred item in ROADMAP §13.3, complementing the weight-only GPTQ / AWQ paths with the activation-quantization story that INT8 GEMM deployment needs. New `src/llm/quantization/smooth.py` exposes `SmoothQuantConfig` (frozen dataclass: `alpha ∈ [0,1]` default 0.5, `search_alpha` toggle, `bits=8` enforced — SmoothQuant is an INT8 method in v1, `group_size=-1` per-channel by design, `sym=True` v1, `layer_policies` for policy-compat validation) plus `SmoothQuantQuantizer` (stateful per-layer processor: `add_batch` accumulates per-channel max-abs activation — O(in_f) memory — then `quantize` produces the packed components) and two model-level entry points `quantize_model_smoothquant` / `quantize_model_smoothquant_with_collector` mirroring the GPTQ / AWQ call conventions (forward-hook per-layer calibration with direct-call fallback, `target_modules` filter, already-quantized refusal, empty-calibration error). The smoothing factor is the paper's `s_j = act_max[j]**alpha / w_max[j]**(1-alpha)`; the per-tensor activation scale has a closed form `max_j(act_max[j]/s_j)/127` (s is constant per channel), so the default path never retains calibration batches. `search_alpha=True` grid-searches {0.25, 0.5, 0.75, 1.0} per layer using the exact quantizer math (`_eval_layer_error`), retaining batches only in that mode. New `src/llm/quantization/_smooth_layer.py` ships `SmoothQuantLinear`: int8 weights with per-output-row fp16 scales, per-tensor fp16 activation scale applied as fake-quantization (round/clamp to INT8) at forward, and an `input_scales` fp16 buffer for the per-channel `x/s` smoothing compensation — mathematically exact, no cross-layer graph analysis (folding `1/s` into the preceding layer and real INT8 GEMM kernels are documented follow-ups). 39 new tests in `tests/quantization/test_smooth_{algorithm,layer,end_to_end}.py` cover: config validation (alpha bounds, bits=8 / group_size=-1 enforcement incl. via `LayerQuantPolicy` overrides — `dataclasses.replace` re-runs `__post_init__`, so invalid policies fail at resolve time; frozen; policy typing); smoothing-scale math (balanced sqrt formula, alpha=0 normalizes weights / alpha=1 normalizes activations, dead-channel scale=1, closed-form activation scale); activation-stat accumulation; **the headline behavioral test — with an activation-outlier channel, SmoothQuant's output reconstruction error is ~an order of magnitude lower than naive INT8 weight+activation quantization without smoothing, and it does not materially degrade on clean activations**; alpha search picking an error at least as good as the naive extreme; packed int8 storage and forward-vs-manual-math equivalence; activation fake-quant bounding to INT8 levels; bias preservation; already-quantized / no-Linear / empty-calib / unmatched-target error paths; forward-failure fallback; policy reject/accept paths; collector entry with `n_samples` cap; and a model-level outlier test. Shared infra: `_single_thread_reductions` moved from `awq.py` into `calibration.py` (both AWQ and SmoothQuant import it; behavior unchanged). Zero regression: the full quantization suite (191 tests incl. all AWQ / GPTQ / simple-PTQ) passes. ADR-010 (`docs/adr/010-smoothquant-integration.md`) records the decision (stats-only scales, closed-form activation scale, in-layer compensation, honest alpha search) and the alternatives rejected (reusing the AWQ layer, per-channel activation scales, cross-layer folding + real INT8 kernels for v1).
- **AWQ integration** (阶段十三 §13.3, P1 量化深化): Activation-aware Weight Quantization (Lin et al., MLSys 2024) as a third orthogonal quantization path alongside simple-PTQ and GPTQ — the ROADMAP's explicitly deferred "AWQ / SmoothQuant / GGUF" first item. New `src/llm/quantization/awq.py` exposes `AWQConfig` (frozen dataclass: `bits ∈ {4,8}`, `group_size ∈ {-1, positive}`, `sym=True` v1, `n_grid` default 20, optional `clip_ratio ∈ (0, 0.5]`, and `layer_policies` for per-layer mixed precision via the ADR-008 `LayerQuantPolicy` abstraction) plus `AWQQuantizer` (stateful per-layer processor: `add_batch` accumulates per-input-channel mean-abs activation — O(in_f) memory, no Hessian — then `search_scale` + `quantize`) and two model-level entry points `quantize_model_awq` / `quantize_model_awq_with_collector` that mirror the GPTQ call conventions (forward-hook per-layer calibration with direct-call fallback, `target_modules` filter, already-quantized refusal, empty-calibration error). The scale search is **group-factorized coordinate greedy**: group quantization decouples along the input dimension, so each input channel is optimized within its group over a power-of-two grid centered on 1, evaluated with the exact per-output-row group quantizer used at packing time and weighted by each channel's mean-abs activation — salient channels get scaled up (`s > 1`, weights amplified, input compensated by `x/s` at forward), which provably reduces their original-space quantization error, while the activation weighting makes the search reject a scale that merely raises the group max for ordinary channels. New `src/llm/quantization/_awq_layer.py` ships `AWQQuantizedLinear`: the same packed 4-bit (two weights/byte) / 8-bit storage convention as GPTQ, plus an `input_scales` fp16 buffer that divides the input per channel — mathematically exact, no cross-layer graph analysis (folding `1/s` into the preceding layer is a documented follow-up). The search's error model equals the packed layer's dequantization by construction (shared `_group_quantize_dequant` / `_pack_weights` math). 42 new tests in `tests/quantization/test_awq_{algorithm,layer,end_to_end}.py` cover: config validation (bits / group_size / n_grid / clip_ratio / frozen / policy typing); activation accumulation (multi-batch equivalence, leading-dim flattening, empty error); **the headline behavioral test — on a salient-channel calibration AWQ's activation-weighted reconstruction error is ~2.5x lower than naive RTN, and on uniform activations it is never materially worse**; search-vs-packing consistency; per-channel (`group_size=-1`) mode; clipping bounds the outlier in the packed reconstruction; packed-storage half-size for 4-bit; forward `x/s` compensation linearity and manual-dequant equivalence; bias preservation; already-quantized / no-Linear / empty-calib / unmatched-target error paths; forward-failure fallback; 8-bit and per-channel e2e; `layer_policies` mixed 8/4-bit dispatch; collector entry with `n_samples` cap; and a model-level salient test. Zero regression: the full quantization suite (152 tests incl. 109 pre-existing GPTQ / simple-PTQ) passes. ADR-009 (`docs/adr/009-awq-integration.md`) records the decision (group-factorized grid search, `s > 1` direction, in-layer compensation, policy reuse) and the alternatives rejected (reusing `GPTQQuantizedLinear`, official-style uniform-ratio grid, cross-layer folding for v1).

- **`NoFreeSlotsError` is pinned to actually ARRIVE at the router** (tests): the router-level tests inject the exception from a mocked generation service, which proves the `except` clause maps the type correctly but not that the type ever reaches it. In production it is raised deep inside `_lock_step_pre` (during `allocate`), travels out of `step()`, and then out of `stream_request`'s generator — which owns a `finally` that reaps sequences and releases slots on every exit path, the natural place for an exception to be lost. - **The per-row sampling catch is pinned to ordinary errors, so fatal ones still propagate** (tests): `_forward_and_sample` isolates each row behind `except (ValueError, KeyError, IndexError)` so one un-samplable request cannot abort a shared batch. - **KV-slot exhaustion was reported as a broken model** (bug, serving): `SlotAllocator.allocate` raised a bare `RuntimeError("No free slots available in KV cache.")`, which fell into the routers' generic `except RuntimeError` and became `model_unavailable` — "the model is broken, give up" — with no retry guidance. The real condition is backpressure: every slot is held by the running batch, and the same request will very likely succeed once it drains. A client following "model unavailable" abandons the request. This is the same shape as `QueueFullError` (the waiting-queue bound) which was already typed for exactly this reason; the KV-slot bound simply never got the treatment, and the two limits are siblings — one bounds requests *waiting to be admitted*, the other those *holding cache memory*. New `NoFreeSlotsError` (a `RuntimeError` subclass, so a route that forgets the typed catch still degrades to the old behaviour rather than escaping as a 500) is raised by the allocator and caught **before** the generic handler in all four router sites, mapping to `queue_full` + `Retry-After: 1` + `x-should-retry: true`. A companion test pins the **control**: a genuine backend `RuntimeError` keeps mapping to `model_unavailable` and carries no retry guidance — without it, the new tests would pass even if every `RuntimeError` had been reclassified, telling clients to retry a permanently broken model forever. One existing test matched the old message text (`pytest.raises(RuntimeError, match="No free slots")`), which is the weak pattern this change exists to remove; it now asserts the **type**.
- **Retryable failures never told the client WHEN to retry — and chat skipped the queue check entirely** (bug, serving): OpenAI's SDK inspects `x-should-retry` first and `Retry-After` second, both **before** its status-code heuristic, and that heuristic retries *every* 5xx. So a bare 503 was already retried, but on the SDK's own curve (`INITIAL_RETRY_DELAY` 0.5s, capped at 8s) — far too eager against a queue that needs a full batching step to drain — and a permanent 503 could not be marked un-retryable at all, because the status code cannot say that. `APIError` gained `retry_after` / `should_retry`, emitted as those two headers from the shared handler (rounded **up**, floored at 1s so a fractional or zero delay never advertises a wait shorter than the real one), and `queue_full` now sends `Retry-After: 1` + `x-should-retry: true` from all four raise sites. Verified against the SDK's real `_should_retry`: our response parses `Retry-After` as `1.0` where a bare 503 parsed `None`, and an explicit `x-should-retry: false` overrides the 5xx heuristic. The same sweep found a **route inconsistency**: `/generate` and `/v1/completions` run the non-streaming pre-checks, but `/v1/chat/completions` did **not** — a full queue surfaced there as the generic "model unavailable" 503 (the backend raises `RuntimeError` once enqueue fails) instead of the honest retryable `queue_full`, and an over-window prompt reached the backend. Chat now runs both checks, matching its own streaming path and the comment on `/generate` that calls them "the non-streaming twin". One existing test scanned a fixed 400-character window of the source to assert the handler maps to `QUEUE_FULL`; splitting the raise across lines to add the retry arguments pushed the assertion out of the window, so it now delimits the handler by the next `except` clause instead of a character count (same intent, immune to formatting) and additionally asserts the handler does *not* map to `MODEL_UNAVAILABLE`.

### Performance

- **Fused OpenAI logit-stage penalty pipeline** (generation hot path): new
  `llm.generation.sampling.apply_penalties` applies the repetition / frequency /
  presence penalties and logit-bias in a single pass — one `[vocab]` clone and
  one id/penalty tensor build instead of up to four clones and up to six
  Python→tensor rebuilds (each a device sync) per decode step. Bit-identical
  to chaining the four individual helpers (3,000 randomized-equivalence trials,
  verified empty/duplicate/out-of-vocab histories and int/str bias keys). All
  decode loops now call it once per token: `eager.stream_generate`,
  `eager.batch_generate`, the continuous-batching `batch_engine`, and both
  `speculative` paths. The four individual helpers remain public API, unchanged
  and independently tested.

- **Scheduler duplicate-check no longer materializes combined lists**
  (serving, minor): `Scheduler.add_sequence_if_not_conflicting` now iterates
  `running` then `waiting` under the lock instead of building
  `list(self.running) + list(self.waiting)` on every enqueue.

- **Vectorized GAE advantage computation** (PPO/RLHF training): new
  `llm.training.rlhf.rollout_buffer._gae_advantages` replaces the per-response
  Python loop in `RolloutBuffer.compute_advantages` (which issued L scalar
  `.item()` device-syncs per sample) with an O(L) vectorized closed form
  (`A_t = gamma*lambda`-decayed reverse cumulative sum). Numerics preserved: the
  reduction runs in float64 to avoid float32 overflow for small
  `gamma*gae_lambda`, keeps the sparse terminal-reward + truncated-
  episode `V(s_L)` bootstrap exactly, and falls back to the stable forward scan
  for pathological near-zero decay. Bit-equal to the loop across 4,000
  randomized configs (worst abs diff ~1e-6); new regression test pins the
  decayed (γ,λ<1) recurrence against an independent reverse scan.

- **Vectorized AWQ per-channel scale search** (quantization calibration): the
  inner candidate sweep of `awq._search_scale` now evaluates all `n_grid`
  power-of-two scale candidates for a channel in one batched pass instead of a
  per-candidate Python loop with a `.item()` reduction — on GPU this removes up
  to 20x kernel launches / device-syncs per channel of the greedy
  coordinate-descent. Per-candidate reconstruction error is computed element-
  wise on the same `[out_f, gs]` slice in the same summation order, so the
  selected (argmin) scale is bit-identical to the sequential sweep (verified
  `torch.equal` across 40 randomized grouped + per-channel configs). Memory is
  bounded by chunking the grid (per-channel mode drops to chunk=1, the original
  footprint). Existing AWQ property tests (salient-channel protection,
  never-worse, packing round-trip) all stay green.

- **`sampling_probs` no longer over-allocates** (generation hot path):
  `sampling_probs` was cloning the full `[..., vocab]` tensor again before
  each in-place top-k / top-p mask, even though `next_logits = logits/temp` was
  already a fresh tensor owned by the function. Both redundant `.clone()`s
  (two full-vocab allocations per call across generation / serving / the
  speculative backend) are removed; the caller's `logits` is still never
  mutated and the output is bit-identical to before (verified across 3,000
  randomized 1-D / 2-D / 3-D configs).

The engine now builds the mask from the real positions, the prefill write keeps only the first occurrence of each (slot, position) pair, and the decode write flattens `start_pos` to `[B]`. Greedy single- and mixed-batch outputs now match the eager backend exactly (verified over multiple prompts with prefix cache on and off). 4 new regression tests (`tests/serving/test_engine.py` ×2, `tests/core/test_kv_cache.py` ×2), red-green verified against all three defects.
- **Dedup + streaming resume without persisted state** (data): `DedupTextSource` with the default in-memory-only state (`write_seen_hashes=False`) is re-created from scratch on checkpoint resume, so the streaming cursor under-counts the skipped inner lines and previously-consumed records are re-yielded as duplicates. `StreamingTextDataModule.setup` now warns when a dedup source lacks persistence and the tutorial documents the requirement (`seen_hashes_path` + `write_seen_hashes=True`) for cross-run dedup consistency. 2 new tests (`tests/data/test_dedup_source.py` ×1, `tests/data/test_streaming.py` ×1), red-green verified.
- **Paged-attention and pad-token sampling defects** (serving + core/paged-attention): three further defects in the continuous-batching engine's serving correctness. (1) `_forward_and_sample` never masked the pad token, so the engine could sample pad and diverge from the eager backend (which masks pad); (2) the paged write appended padded (garbage) K/V for shorter prompts, inflating `seq_lens` and corrupting later decode — it now appends only the real tokens, derived from the attention mask; (3) `paged_attention_forward` did not mask zero-padded key columns (nor future columns during multi-token prefill), so the softmax normalization was distorted — the attention weights now mask padded and future key columns, and multi-token prefill is causal. Also made the dense `update_at_indices` dedup write stable (`torch.sort(..., stable=True)`) so the real token's position-0 write survives instead of a padded slot's. Greedy outputs now match the eager backend for both dense and paged paths across 8 random seeds. Regression coverage: the greedy / mixed-length / paged engine tests in `tests/serving/test_engine.py` and the paged prefill-vs-decode contract in `tests/core/test_paged_attention.py` updated to causal semantics; red-green verified against the defects.
- **Unbounded `stop` list** (serving): the request schemas documented a 4-string cap (OpenAI's limit) but never enforced it — a client could send hundreds of stop strings, making the per-token suffix check unbounded. `GenerationRequest`, `BatchGenerationRequest`, and `ChatCompletionRequest` now validate `stop` with `max_length=4`. 4 new schema tests in `tests/serving/test_schemas.py`, red-green verified.
- **Silent asymmetric-PTQ no-op** (quantization): `QuantizedLinear.from_linear` accepted `symmetric=False` but never computed a zero point — the zero-point buffer stayed zero and the scale was the symmetric one, so the flag silently did nothing (identical dequantization error profile on skewed weights). It now raises `NotImplementedError` (matching `GPTQQuantizedLinear`'s `sym=False` handling); use `symmetric=True` or the GPTQ path for asymmetric quantization. 1 new test in `tests/quantization/test_quantization.py`, red-green verified.
- **Bleu/ChrF empty-input crash** (evaluation): `BleuMetric` and `ChrFMetric` raised inside `sacrebleu` on empty predictions (and forced the optional dependency just to short-circuit), while `RougeMetric`/`F1Metric`/`AccuracyMetric` degrade gracefully. Both now return `{"bleu": 0.0}` / `{"chrf": 0.0}` for empty inputs before importing sacrebleu. 2 new tests in `tests/evaluation/test_generation.py`, red-green verified.
